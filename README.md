#### 📌 ex2: ชนิดข้อมูลและการแปลงค่า (Data Types, `typeof` & Type Conversion)

* **สิ่งที่เราทำ:** สร้างตัวแปร 6 ชนิดข้อมูล ตอบคำถามเกี่ยวกับพฤติกรรมแปลกๆ ของ JavaScript และทดลองแปลงชนิดข้อมูล String เป็น Number
* **แนวคิดและจุดสำคัญ:**
* **การใช้ `typeof`:** เช็กชนิดข้อมูล dynamic จากตัวแปรจริง ไม่ได้พิมพ์คำว่า `"string"` หรือ `"number"` ลงไปเอง
* **ทำความเข้าใจ JS Behavior:**
* `typeof null` ได้ `"object"`
* ตัวแปรที่ยังไม่ได้กำหนดค่า จะมีชนิดเป็น `"undefined"`
* `typeof NaN` (ที่เกิดจาก `Number("abc")`) ได้ชนิดเป็น `"number"`
* **Type Conversion:** ใช้ `Number("20")` แปลง String เป็นตัวเลขก่อนนำไปบวก 5 (ถ้าไม่แปลงจะโดนต่อข้อความกลายเป็น `"205"`) และใช้ `.toFixed(1)` จัดฟอร์แมตทศนิยมเพื่ออ่านได้ในบรรทัดน้ันๆ

#### 📌 ex3: เครื่องคิดเลขคะแนน (Score Calculator & Constants)

* **สิ่งที่เราทำ:** คำนวณคะแนนรวมวิชา CE385 จากคะแนนดิบ 5 ส่วน คำนวณเปอร์เซ็นต์ และหาคะแนนส่วนต่างที่ขาดสำหรับเกรด A
* **แนวคิดและจุดสำคัญ:**
* **หลีกเลี่ยง Magic Numbers:** ตัวเลขเกณฑ์คงที่ทั้งหมด (`60`, `20`, `100`, `80`) ถูกแยกเก็บไว้ในตัวแปร `const` ชื่อตัวพิมพ์ใหญ่ที่สื่อความหมาย เพื่อป้องกันการใช้ตัวเลขดิบกลางสูตร
* **สูตรการคำนวณ:** แปลงคะแนน Workshop ด้วย `(workshopRaw / WORKSHOP_MAX_RAW) * WORKSHOP_WEIGHTED` แล้วนำไปบวกกับคะแนนส่วนอื่นๆ จากนั้นนำคะแนนรวมไปลบออกจากเป้าหมาย `80` (ถ้าคะแนนเกิน 80 ผลลัพธ์จะติดลบตามที่โจทย์ระบุ)
* **ข้อระวังเรื่อง `.toFixed()`:** ใช้ `.toFixed(2)` จัดทศนิยมเฉพาะตอนอยู่ใน `console.log()` เท่านั้น เพราะ `.toFixed()` จะคืนค่าออกมาเป็น String ถ้านำไปบวกต่อเลขจะเพี้ยน

#### 📌 ex4: ระบบตัดเกรดและตรวจรับข้อมูล (Grade Evaluation & Data Validation)

* **สิ่งที่เราทำ:** เขียนฟังก์ชัน `toGrade(score)` รับคะแนน 0-100 แล้วแปลงเป็นเกรด A ถึง F พร้อมรับมือกรณีข้อมูลผิดพลาด
* **แนวคิดและจุดสำคัญ:**
* **Data Validation:** เช็ก `score < 0 || score > 100` หากคะแนนหลุดช่วง 0-100 ให้แสดงข้อความเตือนและสั่ง `return` จบฟังก์ชันทันที
* **ลำดับการเช็ก (Sequence Control):** ต้องเรียง `if / else if` จาก **คะแนนมากไปน้อย** ($80 \rightarrow 75 \rightarrow 70 \dots$) เพราะถ้าเช็กคะแนนน้อยก่อน เช่น `>= 50` คะแนน 80 ก็จะไปติดเงื่อนไข `>= 50` แล้วได้เกรด D ทันที
* **การทดสอบ:** ใช้ลูป `for...of` วนทดสอบ Array คะแนนทั้ง 13 ค่า

#### 📌 ex5: ระบบสั่งอาหารด้วย `switch` (Switch Statement & Fall-through)

* **สิ่งที่เราทำ:** คิดราคาอาหารตามเมนู ขนาด และจำนวน โดยใช้ `switch`
* **แนวคิดและจุดสำคัญ:**
* **Fall-through Pattern:** ยุบรวม `case` เมนูที่มีราคาเท่ากัน 50 บาท (ข้าวผัด, ข้าวมันไก่, ข้าวหมูแดง) ไว้ด้วยกันโดยไม่ใส่ `return` ซ้ำ เพื่อลดการเขียนโค้ดซ้ำซ้อน
* **Default Case:** มี `default` รองรับเมนู/ขนาดที่ไม่มีในรายการเสมอ (เมนูไม่มีในระบบให้ราคา 0 บาท)
* **สูตรคำนวณ:** วนลูป Array ออร์เดอร์ แล้วคิดราคารวมแต่ละรายการจาก $\text{ราคาเมนู} \times \text{ตัวคูณขนาด} \times \text{จำนวน}$

#### 📌 ex6: ระบบตรวจสอบสิทธิ์เข้าใช้งาน (Authentication & Security Workflow)

* **สิ่งที่เราทำ:** เขียนฟังก์ชัน `login()` ตรวจสอบสิทธิ์เป็นลำดับขั้น และตอบคำถามด้านความปลอดภัย
* **แนวคิดและจุดสำคัญ:**
* **Authentication First (ความปลอดภัยมาก่อน):** ต้องตรวจ Username และ Password เป็นลำดับแรกเสมอ เพื่อยืนยันตัวตนก่อน หากตรวจอายุหรือสิทธิ์ก่อน คนนอกที่ไม่รหัสผ่านจะรู้โครงสร้างระบบเราได้ (เกิดปัญหา Information Disclosure)
* **เรียงลำดับการเช็ก:** 1. User/Pass $\rightarrow$ 2. บัญชีถูกระงับ (`isActive`) $\rightarrow$ 3. อายุ (`age`) $\rightarrow$ 4. สิทธิ์ (`role`)
* **Pure Function Design:** ตัวฟังก์ชันใช้การ `return` ข้อความผลลัพธ์เท่านั้น ไม่ใช้ `console.log` ข้างในฟังก์ชัน เพื่อแยกหน้าที่ของโค้ดให้ชัดเจน
